# Prolog component

GNU Prolog 1.5 is the first Class III search engine. It searches bounded rule
spaces and emits a small, versioned text protocol; Python validates that result
and lowers it to a content-addressed artifact. Prolog does not interpret each
inference example.

The original search in `bounded_threshold_search.pl` finds the smallest exact
monotone masked-threshold rule:

```text
popcount(input AND selected_slots) >= minimum_true
```

Inputs are finite lists of true slot indices. The Python bridge bounds selected
width, total examples, candidate count, and wall-clock execution. Results are
either:

```text
PTM_RESULT v1 masked_threshold selected=0,1 minimum=1 mismatches=0
PTM_RESULT v1 no_solution
```

Only integers generated by the bridge enter the temporary Prolog driver. No
user-supplied Prolog terms or arbitrary goals are accepted. `scripts/verify.ps1`
also compiles the search source to a GNU Prolog native object as a compiler
check, while live problem facts are consulted only during bounded search.

Before launch, the bridge rejects a proven monotonicity contradiction: a
positive example that is a subset of a negative example. A nonnegative masked
threshold is monotone, so such a problem cannot have a solution. This safe
pruning avoids a subprocess for XOR-like impossibility certificates; remaining
candidates retain the explicit finite budget and subprocess deadline.

The resulting PA artifact executes through the C++ kernel and versioned C ABI.

## Typed structure search

`bounded_structure_search.pl` adds three independently bounded v2 templates:

- **typed feature-template selection** chooses an exact candidate by numeric
  index. Python owns and validates its field, `DataType`, registry template ID,
  JSON parameters, and coverage before and after the Prolog call. The selected
  result can instantiate the existing `LiteralCatalog` workflow.
- **TA-clause configuration** searches a conjunction of signed literals. Literal
  `2*N` means feature `N`; `2*N+1` means its negation. Results lower to the
  existing `ClauseConfiguration` and `TAClauseConfiguration` schemas.
- **Boolean decision tree** searches explicit false/true branches with a depth
  ceiling and no repeated feature along a root-to-leaf path. The numeric prefix
  result lowers to the fixed `LogicProgram32` kernel for inputs A through E
  when the compiled expression fits its 32-instruction capacity.

Example results use a separate protocol version:

```text
PTM_RESULT v2 feature_template candidate=1 mismatches=0
PTM_RESULT v2 ta_clause literals=0,3 mismatches=0
PTM_RESULT v2 decision_tree nodes=7 depth=2 tree=2,0,2,1,0,1,2,1,1,0 mismatches=0
PTM_RESULT v2 no_solution kind=decision_tree
```

Candidate ceilings are computed in Python before launch: number of typed
candidates, signed-literal combinations, or a conservative read-once tree
recurrence. Example counts, literal width, depth, subprocess time, and repair
iterations also have explicit limits. Python parses only the versioned numeric
protocol and independently evaluates every returned candidate.

## Counterexample-guided repair

`GNUPrologSearch.repair_decision_tree` treats the parent as immutable and
synthesizes a bounded Boolean guard. The repaired result is `parent XOR guard`.
Each iteration verifies the candidate against the complete finite validation
set, adds the first disagreement as a positive or negative flip constraint, and
restarts bounded tree search. Completion requires zero Python-side mismatches;
an exhausted iteration, candidate, or time budget raises a typed failure. The
parent, guard, and combined repair can all lower to fixed Logic programs.

Run `examples/prolog_structures.py` for typed template selection, a signed
clause, an XOR tree, and counterexample-guided repair.

For the supported JSON contract, CLI/TUI workflow, exit statuses, cancellation,
and fixed-Logic export, see [Bounded Prolog search](../docs/bounded-search.md).
